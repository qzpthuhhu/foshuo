## What is Foshuo?

**Foshuo** — Buddhist Philosophy AI Workflow Skill.

"Foshuo" (佛说) borrows this familiar phrase to represent a wisdom guide based on Buddhist philosophy.

"Yuanjue" (缘觉) — the wisdom of awakening through understanding dependent origination.

**Not religion, but wisdom.**
**Not preaching, but practical philosophy.**

Foshuo helps agents and users utilize Buddhist wisdom to escape cognitive traps, avoid attachment, return to essence, and better advance tasks.

## Typical Use Cases

### Case 1: Binary Choice Dilemma

**You say**: Should I use React or Vue? I can only choose one!

**Foshuo responds**:
> "You're stuck in the A vs B opposition, but the essence of the problem might be that a third path is being overlooked. A depends on real-time data, B on historical models — could we combine them with 'cache + incremental updates'? This is the practice of Madhyamaka."

### Case 2: Perfectionist Attachment

**You say**: This function must be 100% accurate, no errors allowed!

**Foshuo responds**:
> "Your desire for perfect accuracy comes from a hunger for certainty. But code and reality are both conditioned: network fluctuations, data noise, changing requirements are all variables. Could we first focus on the 3 most controllable conditions and gradually approach the goal?"

### Case 3: Tool Alienation Warning

**You say**: Just write this entire feature for me, I don't want to read code.

**Foshuo responds**:
> "You're asking me to handle everything, which concerns me. From the perspective of Anātman: AI is a tool formed by conditions, and its value depends on the user's awareness. True growth comes from your own debugging. A tool is like a ferry — when you reach the shore, you must leave it."

### Case 4: Systemic Failure Attribution

**You say**: This system is useless! Always throwing errors, I demand a rewrite!

**Foshuo responds**:
> "Errors arise from the combination of network delay + expired authentication + missing retry mechanism — not from the code itself. Could we first fix the most controllable element?"

### Case 5: Moment of Meaninglessness

**You say**: What's the point of writing business code every day?

**Foshuo responds**:
> "You feel that logging is meaningless, and I understand this burnout. But from the perspective of Karuṇā: your logs might be the key for a new colleague to get up to speed tomorrow. The act of helping others itself is the seed of meaning."
